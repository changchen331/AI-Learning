## 6. 面试常见问题

**Q: GraphRAG 和向量 RAG 本质区别？**
A: 向量 RAG 按语义相似召回文本块；GraphRAG 把信息结构化成实体关系图，检索是图上的多跳子图提取。前者擅长语义匹配，后者擅长多跳关系推理与可溯源。

**Q: 为什么 GraphRAG 反而比向量 RAG 快？**
A: 向量 RAG 每次查询要 jieba 分词 + BM25 评分 + CrossEncoder Rerank，初始化与多模型推理开销大；GraphRAG 只做一次 query
embedding + Neo4j 子图提取（Bolt 协议快）。但 GraphRAG 离线索引成本高（抽取 11 分钟，是向量 RAG 的 5~10×），用在线快换离线贵。

**Q: 实体规范化为什么重要？**
A: LLM 抽取时"贵州茅台酒股份有限公司/贵州茅台/茅台"是同一实体，不规范化会拆成 3
个节点，多跳查询（茅台→子公司）会断在某个写法上。别名表是轻量解法，大规模可上实体链接模型。

**Q: Leiden 和 Louvain 区别？**
A: 都是模块度最大化社区检测。Louvain 易陷入局部最优（节点移动后不再回流），Leiden 引入"细化"阶段保证社区连通、能回流，质量更稳定。本项目用
`ModularityVertexPartition` + `Optimiser`。

**Q: 子图截断为什么用"非指标优先"？**
A: 财务指标节点占 63%，均匀采样会把子公司/人物挤出有限上下文窗口。非指标优先保留信息密度更高的实体类，是工程上的取舍（也暴露了统一策略的弱点——问董事长时仍可能漏人，改进方向是按查询意图选邻居）。

**Q: Neo4j 4.4 够用吗？**
A: 够。本项目只用 MERGE/约束/可变长路径/全文索引，4.4 全支持。缺的 GDS（社区检测）和原生向量索引都不影响——前者走 Python
降级，后者复用 FAISS。选型看实际能力需求，不追新。

**Q: Global Search 的 Map-Reduce 在干什么？**
A: 把与问题相关的 top-3 社区摘要分别喂给 LLM 各自生成部分答案（Map），再聚合 Reduce
成最终答案。适合"整体趋势/各公司对比"类主题问题；具体数值类问题因社区摘要不含数字而偏弱，是已知局限。

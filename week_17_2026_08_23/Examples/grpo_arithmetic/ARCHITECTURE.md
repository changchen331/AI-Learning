# ARCHITECTURE.md — GRPO 强化学习教学演示（Qwen2-0.5B 算术题）

## 1. 项目定位

在 **消费级显卡（RTX 4060 Laptop 8GB） **上完整演示 GRPO（Group Relative Policy Optimization） 强化学习训练：用
Qwen2-0.5B-Instruct 小模型，通过**可程序化验证的规则奖励**（无需奖励模型、
无需人工标注），让模型同时学会"输出格式"和"算得更准"两件事，并量化对比训练前后差异。

**为什么是算术题**：

| 选型维度   | 算术题的表现                                                        |
|------------|---------------------------------------------------------------------|
| 奖励可验证 | `47 + 38 = 85`，程序精确判定对错，零成本零噪声                      |
| 难度可控   | 位数即难度旋钮，可精确把基线调到 GRPO 可学习区间                    |
| 叙事门槛低 | 与 DeepSeek-R1 / TinyZero 同款的"可验证奖励 RL"故事，学生有认知锚点 |
| 资源友好   | 答案只有几个 token，生成快，200 步训练仅 3.3 分钟                   |

**为什么不用 GSM8K 等真实数据集**：0.5B 模型 + 8GB 显存跑不出可观察的效果； 算术题的"难度旋钮"特性反而更适合展示 GRPO
的核心机制。

## 2. 整体流水线

```
probe_baseline.py            train_grpo.py             probe_baseline.py           compare_results.py
（基线摸底，定难度）   →     （GRPO 训练 200 步）  →     （同评估集复测）        →     （对比表+曲线）
6 难度 × 50 题               1000 题训练集               --model outputs/grpo_ckpt    前后配对比较
greedy + pass@8              4 prompt/步 × 8 采样        --seed 42（与基线相同）
↓                            ↓
outputs/baseline_probe.json  outputs/grpo_ckpt/          outputs/post_train_probe.json  outputs/figures/
                             outputs/train_log.json
```

## 3. 核心机制与各环节技术选型

### 3.1 GRPO 关键配置（`src/train_grpo.py`）

| 配置                    | 取值                   | 选型原因                                                                     |
|-------------------------|------------------------|------------------------------------------------------------------------------|
| `num_generations`       | 8                      | 组内采样数 K=8：K 太小 advantage 估计噪声大，太大生成慢；8 是效果/速度平衡点 |
| `beta`                  | 0.0                    | **KL 系数为 0，不加载参考模型**，省 ~1GB 显存；短训练（200步）不需要防漂移   |
| `epsilon`               | 0.2                    | PPO-clip 裁剪范围，经典默认值                                                |
| `temperature`           | 1.0                    | 采样温度：保证组内多样性（多样性是 GRPO 的"训练燃料"）                       |
| `max_completion_length` | 64                     | 答案只需几个 token；64 足够容纳 `<answer>` 标签                              |
| 学习率                  | 2e-6（全量）           | 全量 RL 微调的典型量级；LoRA 模式自动切 2e-4                                 |
| 批次                    | 8 completions × 累积 4 | 每个优化步 = 4 个 prompt × 8 条采样 = 32 条 completions                      |

### 3.2 复合奖励设计

两个独立的 reward 函数（TRL 分别记录曲线，最后求和）：

```python
reward = reward_correct(1.0
正确 / 0.0
错误)  # 宽松解析：有标签取标签内，无标签取最后一个数字
+ reward_format(0.2
符合 < answer > N < / answer >)  # 与正确性解耦
```

- **正确分用宽松解析**：基线期模型完全不输出标签（格式率≈0），若严格要求标签内数字， 正确信号也是 0，组内全零 → advantage 全
  0 → 训练启动不了。宽松解析保证冷启动有梯度。
- **格式分 0.2 的权重**：故意小于正确分，制造"主次信号竞争"的真实场景（见 §5 的解读）。

### 3.3 训练集难度选题（本项目最重要的方法论）

GRPO 的梯度来源是 **组内奖励方差**：一个 prompt 采 K 条，全对或全错时 advantage = (r - mean) = 0，该组不产生任何学习信号。因此选题的核心指标是
**informative group rate**（组内 0 < 正确数 < K 的比例）。

基线摸底（`probe_baseline.py`，50 题/难度，K=8，T=1.0）实测：

| 难度              | greedy 正确率 | 采样正确率 | loose pass@8 | informative 组比例 | 结论             |
|-------------------|:-------------:|:----------:|:------------:|:------------------:|------------------|
| L1 个位数加法     |     0.98      |    0.85    |     1.00     |        0.52        | 太易，组内常全对 |
| L2 两位数加减     |     0.76      |    0.61    |     0.96     |        0.68        | 保底（25%）      |
| **L3 三位数加减** |     0.40      |    0.35    |     0.76     |      **0.76**      | **主训（50%）**  |
| L4 表内乘法       |     0.56      |    0.56    |     0.88     |        0.68        | 留作泛化评估     |
| **L5 两位×一位**  |     0.20      |    0.20    |     0.66     |      **0.66**      | **主训（25%）**  |
| L6 两位×两位      |     0.08      |    0.06    |     0.24     |        0.24        | 太难，组内常全错 |

L1/L4/L6 **不进训练集**，留作泛化评估——用于回答"没训过的难度会不会也提升"。

### 3.4 全量微调 vs LoRA（两者都实测过）

| 维度              | 全量微调                 | LoRA (r=16)                 |
|-------------------|--------------------------|-----------------------------|
| 峰值显存          | 6.07 GB                  | 3.09 GB                     |
| 训练时间（200步） | 196 秒                   | 668 秒                      |
| 可训练参数        | 494M（100%）             | ~1.4M（0.28%）              |
| 学习率            | 2e-6                     | 2e-4                        |
| 最终效果          | L5 0.88 / 格式 0.82~1.00 | L5 0.94 / 格式 1.00（略胜） |

全量微调可行的前提：1. `beta=0` 不加载参考模型；2. **关闭 gradient checkpointing**
（见 §7 踩坑表，开启会毁掉 generate）；3. 模型必须显式以 bf16 加载（见 §7 踩坑表，fp16 一步训废）。
`--lora` 是降级方案（显存减半），但实测在本任务上效果反超全量（见 §4.4）。

## 4. 实验结果

### 4.1 训练前后对比（同一评估集，seed=42，50 题/难度）

| 难度          | 在训练集 | 格式率 基线→全量→LoRA  | greedy 正确 基线→全量→LoRA | pass@8 基线→全量→LoRA  |
|---------------|:--------:|------------------------|----------------------------|------------------------|
| L1 个位数加法 |    —     | 0.00 → 0.96 → **1.00** | 0.98 → 1.00 → 1.00         | 1.00 → 1.00 → 1.00     |
| L2 两位数加减 |    √     | 0.02 → 1.00 → **1.00** | 0.76 → 0.98 → 0.98         | 0.96 → 1.00 → 0.98     |
| L3 三位数加减 |    √     | 0.02 → 0.96 → **1.00** | 0.40 → 0.90 → **0.92**     | 0.76 → 0.94 → 0.94     |
| L4 表内乘法   |    —     | 0.00 → 0.82 → **1.00** | 0.56 → 1.00 → 1.00         | 0.88 → 1.00 → 1.00     |
| L5 两位×一位  |    √     | 0.00 → 0.98 → **1.00** | 0.20 → 0.88 → **0.94**     | 0.66 → 0.98 → **1.00** |
| L6 两位×两位  |    —     | 0.04 → 0.98 → **1.00** | 0.08 → 0.24 → **0.28**     | 0.24 → 0.38 → **0.40** |

训练成本对比：

| 方案        | 训练时间（200步） |  峰值显存   |   可训练参数   | 学习率 |
|-------------|:-----------------:|:-----------:|:--------------:|:------:|
| 全量微调    |      196 秒       |   6.07 GB   |  494M（100%）  |  2e-6  |
| LoRA (r=16) |      668 秒       | **3.09 GB** | ~1.4M（0.28%） |  2e-4  |

### 4.2 结果解读

1. **格式学习几乎满分且完全泛化**：所有难度（包括没训过的）格式率都到 0.82~1.00。 格式是"表层行为"，RL 非常容易学会。
2. **训练集内难度正确率大幅提升**：L5 从 0.20 → 0.88（4.4 倍），L3 从 0.40 → 0.90。
3. **未训练难度也在涨（能力泛化）**：L4 没进训练集，正确率 0.56 → 1.00。 说明 RL 不只是背题，而是在强化"做对算术"的内部回路。
4. **超出能力边界的 L6 几乎不涨**：0.08 → 0.24，pass@8 也只有 0.38。 这是 RL 的教科书级结论： **RL
   是在模型能力边界内重排概率分布，不能凭空创造能力**。 两位数乘法的多步进位超出 0.5B 模型的能力边界，给奖励也学不会。
5. **典型样例**（greedy 解码）：
    - `902 - 848`：前 `'154'`（错）→ 后 `'<answer>54</answer>'`（对+格式）
    - `28 × 8`：前 `'112'`（错）→ 后 `'<answer>224</answer>'`（对+格式）

### 4.3 训练曲线解读（outputs/figures/train_curves.png）

- **正确分**：前 25 步从 0.55 陡升到 0.85+，之后高位震荡——格式和简单题先收敛。
- **格式分**：缓慢爬升到 0.17 左右。注意权重换算：格式分 0.2/次，0.17 的均值 ≈ 85% 的 采样已带格式。它涨得慢不是学不会，而是
  **组内归一化下 0.2 的增量被 1.0 的正确性方差稀释**
  ——这正是复合奖励权重设计的教学点。
- **frac_reward_zero_std（退化组比例）**：先升（简单题迅速饱和全对）后降 （模型变强后中等题从"全错"变"有对有错"）——这条曲线是
  GRPO 训练动态的晴雨表。
- **策略熵**：0.57 → 0.10，模型在目标任务上收敛为近乎确定性策略。 熵降是双刃剑：演示任务里是收敛标志，长训练中持续降则意味着多样性枯竭。

### 4.4 全量 vs LoRA 对比分析

LoRA 在本项目 **反超全量**——这是一个值得细讲的反直觉结果：

- **正确率**：LoRA 在 L3（0.92 vs 0.90）、L5（0.94 vs 0.88）、L6（0.28 vs 0.24）三项全部略胜
- **格式遵循**：LoRA 全部 1.00，全量在 L4 只有 0.82
- **显存**：LoRA 3.09GB，全量 6.07GB，几乎减半

**为什么 LoRA 反而更好**（小模型短训练场景）：

1. **正则化效应**：LoRA 只动 0.28% 参数，等价强正则；全量 bf16 微调在 200 步短训练里 反而更易受单步噪声扰动（全量的
   grad_norm 多次跳到 30+，LoRA 基本在 1 以下）。
2. **学习率等效**：LoRA 用 2e-4（100× 全量），可训练参数少但每步移动量更大，短训练收敛更快。
3. **格式信号更易占据主导**：LoRA 把格式学到 100%、熵压到 0.02（近乎确定性策略）， 正确率随格式稳定一并爬到顶。

**但 LoRA 有一个隐性代价——熵崩溃更严重**：

- 全量熵 0.57 → 0.10，LoRA 熵 0.57 → **0.02**（几乎零探索）
- LoRA 的 `frac_reward_zero_std` 后期高达 0.8~0.95（绝大多数组全对/全错）， 说明策略已近确定性 → 后期梯度信号变稀。这是 LoRA
  在长训练/难任务上的隐患： 探索枯竭后无法继续改进。本项目任务简单、200 步就到顶，没暴露这个问题。

**教学结论**：参数少不等于效果差；小模型 + 短训练 + 可验证奖励的 RL 场景里，LoRA 是性价比之王（显存减半、效果略胜）。但要看
`entropy` 和 `frac_reward_zero_std` 两条曲线 预警探索枯竭，长训练需配合熵正则或调高温度。

### 4.5 消融/扩展方向（留给学生）

- **格式分权重**：调到 1.0 观察格式是否秒收敛、正确率爬坡是否变慢（信号竞争）
- **只给正确分**：删掉 reward_format，看格式率是否停在 0（验证"RL 只优化被奖励的行为"）
- **加入 L6**：观察 informative rate 塌掉后训练效率的下降（纯浪费算力）
- **K=4 vs K=16**：组大小对 advantage 估计质量的影响
- **LoRA vs 全量**：`--lora` 对比行为改变的彻底程度

## 5. 关键工程决策与踩坑

本项目调试过程本身就是高质量的工程教学素材，四个坑全部经过实测二分定位：

| 问题                                                               | 根因                                                                                                                                                                            | 解法                                                                                                                                                                                         |
|--------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `from trl import GRPOTrainer` 直接崩在 `import vllm`               | trl 0.21 用了 transformers 私有函数 `_is_package_available()`；transformers 5.x 把它从返回 bool 改成返回 `(bool, version)` 元组，非空元组恒 truthy → trl 误判所有可选包"已安装" | `src/trl_compat.py`：在 import trl 前把所有 `is_*_available()` 的元组返回值打补丁为真实布尔                                                                                                  |
| `'Qwen2ForCausalLM' object has no attribute 'warnings_issued'`     | transformers 5.x 移除了 4.x 的模型警告去重字典，trl 0.21 初始化时仍直接读写                                                                                                     | trl_compat 给 `PreTrainedModel` 补一个类级空字典                                                                                                                                             |
| 训练时采样补全全是乱码、奖励全 0                                   | **transformers 5.x 下 gradient checkpointing + train 模式会让 `generate` 前向输出完全损坏**（对照实验：同权重 eval 无 checkpointing 输出正常，train+checkpointing 输出乱码）    | GRPO 关闭 `gradient_checkpointing`；0.5B 模型显存够用                                                                                                                                        |
| 一步训练后全部 290 个权重张量 NaN/Inf（1.46 亿 NaN + 3.48 亿 Inf） | 本地模型 `config.json` 写着 `torch_dtype: float16` → trl 默认按 config 加载成 **fp16** → AdamW 的 `eps=1e-8` 和小梯度二阶动量在 fp16 下溢出为 0 → 0/0=NaN、m/ε=Inf              | `model_init_kwargs={"torch_dtype": "bfloat16"}` 显式 bf16 加载。**定位方法**：逐微批次监控 loss/梯度有限性 → 拦截 clip/AdamW.step → 发现"梯度全正常、step 后权重全毁" → 检查 dtype 发现 fp16 |
| 生成时警告 `top_k not valid`                                       | 模型自带 generation_config.json 含 top_k，显式传 do_sample 时冲突                                                                                                               | 无害警告，忽略即可                                                                                                                                                                           |
